## Conclusión por repo

**1. Expo-React-native-pose-detection-demo.** Existe, pero es un demo pequeño (4 estrellas, 48 commits) y sin actividad desde noviembre de 2025. No tiene licencia, así que legalmente no se puede copiar ni derivar código. Es útil solo como referencia de arquitectura: Expo Module nativo con MediaPipe Pose Landmarker, VisionCamera para los frames y Skia para dibujar el esqueleto. Está fijado a VisionCamera v4, que ya no se mantiene, y a Expo 53. Sus últimos commits indican que la orientación (de pie, frontal, lateral) aún tenía problemas de precisión.

**2. state-of-health-tracker.** Existe y está activo y bien mantenido (480 estrellas, release 2.0.1 en julio de 2026, última actividad en septiembre de 2026). Pero no es un repo de pose: es un tracker de entrenamientos, macros y carreras. Su único valor para nosotros es de referencia de producto y de stack (RN 0.86, Expo SDK 57 según el README). No encontré licencia, así que no se debe copiar código. El informe lo cita de forma engañosa si se presentaba como fuente de detección de pose.

**3. react-native-fast-tflite.** Existe, es MIT y está activo (último commit 2026-09-11), con la URL canónica bajo `margelo/`, no `mrousavy/` (la URL de mrousavy no se consultó directamente). Soporta Expo mediante config plugin, pero necesita prebuild/dev build, y depende de Nitro Modules. No incluye ningún modelo de pose: habría que aportar un .tflite (por ejemplo MoveNet o BlazePose) y escribir el pre y postprocesado. Es la opción más flexible para una implementación 100% TFLite on-device. No pude verificar la versión mínima de RN ni si exige la nueva arquitectura.

**4. free-exercise-db.** Existe, con Unlicense (dominio público según la página) y ~2.1k estrellas, y recibió commits hasta septiembre de 2026. Ofrece 800+ ejercicios en JSON con imágenes JPG (normalmente 2 por ejercicio, pose inicial y final). Es la fuente más limpia en licencia para catálogo y metadatos. Debilidades: datos incompletos en algunos campos, imágenes duplicadas y calidad fotográfica irregular. La procedencia original de las imágenes no está documentada en la página, así que conviene una revisión legal ligera antes de publicar.

**5. RepDB/exercise-dataset.** Existe (la URL correcta es `RepDB/exercise-dataset`) y es el más activo de los datasets (v1.50, 701 ejercicios, 27-oct-2026). Tiene imágenes WebP planas de 512 px, consistentes en estilo, más ligeras que JPG. Pero no es abierto: la licencia exige atribución visible, prohíbe redistribuir como dataset o API y prohíbe el uso con IA generativa, y las animaciones de calidad son de pago. Es una opción viable solo si aceptamos esas condiciones y la dependencia de un proveedor comercial. Lo de empaquetarlo offline dentro de la APK no está tratado explícitamente; hay que preguntarlo al autor.

**6. react-native-vision-camera.** Existe, es MIT y es el repo más sólido (9.6k estrellas, commit del 2026-10-14). Se movió a la org Margelo. Ofrece frame processors con worklets, pero no incluye detección de pose. V5 (reescrita con Nitro) rompió el sistema de plugins anterior, por lo que los plugins de pose de la era v4 no sirven sin portarlos. Hoy habría que combinar VisionCamera v5 con fast-tflite (modelo TFLite propio) o con un módulo nativo propio sobre MediaPipe/ML Kit. No pude verificar en fuente primaria el soporte de Expo ni de la nueva arquitectura; hay que comprobarlo en la documentación oficial antes de fijar versiones.

## Recomendación final

**Usar como base (dependencias):**
- `react-native-vision-camera` v5 (MIT, activo) para la cámara y los frame processors.
- `react-native-fast-tflite` (MIT, activo) para ejecutar el modelo de pose on-device, con un modelo como MoveNet o BlazePose elegido y evaluado aparte. Alternativa: un módulo nativo propio con MediaPipe Pose Landmarker en Android, siguiendo el patrón del demo.
- `yuhonas/free-exercise-db` como catálogo de ejercicios por su licencia (Unlicense), tras revisar la procedencia de las imágenes y completar campos faltantes.

**Solo referencia (no copiar código):**
- `mantu-bit/Expo-React-native-pose-detection-demo` (patrón de Expo Module + MediaPipe + Skia; sin licencia, desactualizado).
- `Kennygunderman/state-of-health-tracker` (referencia de producto y stack Expo 57; sin licencia visible y sin pose).
- `RepDB/exercise-dataset` como alternativa de imágenes WebP más pulidas, solo si el equipo acepta atribución visible y restricciones, y tras aclarar el empaquetado offline con el autor.

**Descartar:** ninguno de forma definitiva, pero descarta usar el demo (1) o el tracker (2) como base de código por falta de licencia. Tampoco recomiendo plugins de pose de VisionCamera v4 ni `expo-pose-landmarks`/`react-native-vision-camera-mlkit` sin antes probar su compatibilidad con v5 (no verificada).

**Pendientes antes de decidir:**
1. Confirmar en la documentación oficial de VisionCamera v5 y fast-tflite las versiones mínimas de RN/Expo SDK y si exigen nueva arquitectura. No pude acceder a margelo.com.
2. Verificar licencias reales (archivos LICENSE) de los repos 1 y 2 con acceso a la API de GitHub.
3. Hacer un prototipo con un modelo de pose real en un dispositivo Android de gama media para medir FPS y precisión.
